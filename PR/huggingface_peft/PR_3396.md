## Summary

This PR addresses two core engineering issues in PEFT's LoRA implementation:

### Issue 1: Dead Code in get_delta_weight()

The `get_delta_weight()` methods in `Linear`, `Embedding`, and `_ConvNd` layers contain dead code that wastes memory bandwidth. When `cast_to_fp32=True` (CPU + bf16/fp16 scenario), the code calls `.float()` which creates a **copy** of the tensor, performs computation on the copy, then attempts to write back the unmodified copy to the original weights. This is ineffective because:

- `.float()` creates a new tensor, leaving the original unchanged
- The write-back operations assign the same values back to themselves
- This wastes memory bandwidth without any functional effect

**Files affected**: `src/peft/tuners/lora/layer.py`
- `Linear.get_delta_weight()` (lines 994-996)
- `Embedding.get_delta_weight()` (lines 1318-1320)  
- `_ConvNd.get_delta_weight()` (lines 1689-1691)

### Issue 2: Dtype Inconsistency in Linear.merge() Unsafe Path

The unsafe merge path in `Linear.merge()` lacks explicit dtype conversion, creating inconsistency with:
- Safe merge path in `Linear.merge()` (line 904)
- Unsafe merge path in `_ConvNd.merge()` (line 1622)

**Fix**: Added `.to(orig_dtype)` to ensure all merge paths handle dtype consistently.
