## PR 描述

## Summary

Refactors StateMachine to extract transition rules as configurable parameter and adds lifecycle hooks (before/after transition) for extensibility.

## Problem

The StateMachine had hardcoded transition rules and no way to hook into the transition lifecycle. This limited flexibility for custom validation, logging/monitoring, and custom workflows.

## Changes

- Added `transition_rules` parameter to `StateMachine.__init__` (defaults to `VALID_TRANSITIONS`)
- Added `on_before_transition(hook)` method - hooks can block transitions by raising exceptions
- Added `on_after_transition(hook)` method - errors are logged but don't block transitions
- Added `get_transition_history()` method returning list of `{from, to}` dicts for audit trail
- Changed `is_valid_transition` from static method to instance method using `_transition_rules`
- Added comprehensive tests in `tests/test_state_machine_hooks.py`

## Benefits

- **Flexibility**: Custom transition rules for different workflows
- **Extensibility**: Hooks allow custom logic without modifying core
- **Observability**: Transition history provides audit trail
- **Backward Compatible**: All changes are additive
