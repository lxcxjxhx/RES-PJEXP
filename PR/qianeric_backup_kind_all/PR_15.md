## PR 描述

## Summary

Enhances EventBus with async error handling, per-handler timeouts, and priority-based execution.

## Problem

The EventBus lacked advanced async features needed for production use:
- No timeout handling for async handlers (slow handlers could block the system)
- No priority system (handlers executed in registration order)
- Limited error handling (only logging, no control over behavior)

## Changes

- Added `priority` parameter to `subscribe()` method (default: 100, lower = higher priority)
- Added `default_timeout` parameter to `EventBus.__init__()`
- Enhanced `publish_async()` with `timeout` and `error_policy` parameters
- Error policies: "log" (default), "raise", "ignore"
- Handlers stored as `(priority, handler)` tuples, sorted by priority
- Timeout uses `asyncio.wait_for()` for async handlers
- Updated `unsubscribe()` to work with new tuple structure
- Added comprehensive tests in `tests/test_event_bus_async.py`

## Benefits

- **Reliability**: Timeout prevents slow handlers from blocking critical operations
- **Control**: Priority system ensures critical handlers run first
- **Flexibility**: Error policies allow different strategies for different use cases
- **Backward Compatible**: All changes are additive with sensible defaults
